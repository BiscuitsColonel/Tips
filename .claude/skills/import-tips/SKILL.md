# 外部のメモを Tips に取り込む

残すかどうかの基準・書き方・載せない情報は `.claude/rules/writing.md` が正本。この Skill は、その基準で大量のメモをさばく手順と、実際に踏んだ落とし穴を持つ。

## 流れ

1. 棚卸し: 取り込み元を全件列挙して TSV にする
2. 仕分け: 1件ずつ本文を読んで判定する
3. 書き起こし: 残すものを Tip にする
4. 検査: `scripts/check-tips.py` を通す
5. コミット・PR: 判定ログの要約を PR 本文に載せる

件数が多いとき（目安 50 件超）は、2〜3 を書き込み先のカテゴリ単位でサブエージェントに分ける。

## 1. 棚卸し

列は `fileId（またはパス）, 元の場所, 形式, 更新日, 分類, 推奨カテゴリ, 理由`。scratchpad など、リポジトリの外に置く。

- 対象は本人がオーナーのものだけ。共有されたもの・他人の共有ドライブは見ない
- 私的なフォルダ（転職・メール・物件など）は、配下のファイル名を一度見て、技術メモが無いことを確かめてから、フォルダ単位で1行にまとめて外す
- 4GB を超えるアーカイブや、画像・動画は棚卸しから外す。外したことは報告に書く

## 2. 仕分け

判定は `writing.md` の「残す基準」と「判断の例」に従う。

- **全件、本文を読んでから判定する。** 棚卸しの理由欄やファイル名だけで DROP にしない。今回、担当の1人が約 100 件を理由欄だけで落としていて、全件を読み直させたら残すものが 7 件から 13 件に増えた
- 読めなかったものは DROP ではなく「未読」としてログに残し、報告に挙げる
- 大きいファイルは冒頭と見出しだけ読んでもよい。その場合はログに「冒頭のみ」と書く
- 他人の資料（スライド・PDF・Web 記事の保存）は原則落とす。他で手に入らない一次情報だけ残す
- 勤務先・顧客の資料、自作プロジェクトの扱いは `writing.md` の「載せない情報」「自作のコード」に従う

判定ログは `fileId, 元の場所, 判定(KEEP/DROP/MERGED/未読), 出力先, 理由` の TSV にする。KEEP の理由には「何が AI で出せない価値か」を書く。

## 3. 書き起こし

- 関連する複数のメモは1本にまとめる。小さいファイルを乱立させない
- 冒頭に元メモの時点を書く（例「（2021-09 時点のメモ。PostgreSQL 12 で検証）」）
- 元メモに無い知識（EOL・仕様変更・既定値）を足すのは、公式ドキュメントで確かめられたものだけにし、出典 URL を付ける。確かめられないものは書かない。今回、知識で足した補足のうち裏取りを求めたものは、1つずつ確かめてから出典を付けた
- 元の記録で結論が出ていないもの（「推定」「見込み」）は、本文でもそう書く。言い切らない
- 認証情報は実値を一切書かない。例示は `<password>` のようなプレースホルダにする

## 並行で進めるときの決まり

- 書き込み先のディレクトリが重ならない単位で分ける（例: DB / AWS・Terraform / OS・ネットワーク / HA・監視 / 設計・言語）。担当外のカテゴリに置くべきものは書かずに「REASSIGN」としてログに残させる
- 既存の Tip を同時に整理するなら、担当には既存の md へ追記させず、新しいファイルに書かせる。整理は全員が終わってから行う
- サブエージェントには git の操作と README の編集をさせない。コミットと README の再生成は呼び出し元がまとめて行う
- Windows で書かれたファイルは CRLF になる。`.gitattributes` で LF に正規化しているので、コミット前に `git add --renormalize .` を通す。混ざったままだと、以後の修正でファイル全体が差分に出る
- 戻ってきた結果は、そのまま受け入れない。件数・未読・知識で足した補足を確かめ、基準から外れていれば差し戻す

## 取り込み元ごとの落とし穴

- **Google Drive（MCP）**: `read_file_content` が空で返る大きいファイルは、`download_file_content` を使う。結果が大きすぎるときは、自動でファイルに保存される。その JSON から base64 を取り出してデコードする
- **Shift-JIS のテキスト**: MCP の読み取りでは日本語が化ける。ダウンロードした bytes を `cp932` でデコードする。小さいファイルは base64 が会話に直接返り、ファイルに保存されない。手で書き写すと誤りが入るので、大きいファイルと同じ経路を取れないときは「未読」で残す
- **gws CLI**: 認証が切れていると `invalid_grant` で失敗する。再認証は本人が `! gws auth login` で行う
- **認証情報入りのファイル**: 判定のために読むのはよいが、ログや報告にも値を書かない。「どのファイルに何の種類があったか」だけを書く

## 4. 検査

```sh
$ python scripts/gen-readme.py
$ python scripts/check-tips.py
```

`check-tips.py` は見出し・リンク・README のずれ・認証情報のパターン・`.claude/sensitive-words.local.txt` の語を見る。勤務先や顧客の名前で、まだリストに無いものが出てきたら、このローカルファイルに足す（リポジトリには書かない）。

正規表現では拾えない識別情報（システム名、特徴的な構成の組み合わせ、業界が分かる語）は、`reviewer` サブエージェントに差分を渡して見させる。

## 5. コミット・PR

- 取り込み・既存の整理・ルールの変更は、別々のコミットにする
- PR 本文には、件数（候補・残した・落とした・未読）、追加したカテゴリ、削除した既存の Tip の一覧、取り込まなかったものとその理由を書く
- 作業中に scratchpad に置いた棚卸し・判定ログ・デコードしたファイルには、認証情報の在りかが含まれる。残すか消すかは本人に聞く
