# EBS スナップショットから EC2 を復旧する手順と、AWS Backup から EFS を復元したときの置き場所

（2021-11 時点のメモ）EC2 の EBS ボリュームを戻す手順と、AWS Backup で EFS を復元したときにファイルがどこに出てくるか。

## EC2 を EBS スナップショットから戻す

作業を始める前に、戻す前の状態を控える（インスタンス ID、EBS ID、タグ）。AWS 側のタグ（バックアップ対象を決めるタグなど）は、新しいボリュームには引き継がれないので、控えて付け直す。

1. インスタンスを停止する（ステータスチェックが 2/2 に戻っていることを確認する）
2. 現在の EBS ボリュームの ID を控える
3. スナップショットからボリュームを作成する。控えたタグを追加する。AZ はインスタンスと同じにする
4. 現在のボリュームをデタッチし、新しいボリュームをアタッチする（デバイス名を元のルートデバイスと合わせる。例: `/dev/xvda`）
5. インスタンスを起動し、ステータスチェックが 2/2 になることを確認する
6. 古い EBS を削除する（確認が終わってから）

古い EBS の削除は最後に回す。起動に失敗したときに、元の状態へ戻せる。

## AWS Backup から EFS を復元する

復元したファイルは、元のディレクトリへ上書きされない。マウント先の直下に `aws-backup-restore_<復元時刻のタイムスタンプ>` というディレクトリが作られ、その下に戻る。そこから元の場所へコピーする。

- 全体を戻すなら、共有フォルダ全体を復元する。ディレクトリやファイル単位の復元もできる（項目レベルの復元）
- 項目レベルの復元では、復元する項目のパスを指定する。EFS をマウントしているディレクトリを省いて書く（`/home` にマウントしていて、戻したいのが `/home/hoge.txt` なら、パスは `/hoge.txt`）
- 復元先は「ソースファイルシステムのディレクトリ」を選ぶと、元のファイルシステムの中に `aws-backup-restore_...` ができる
- 復元の IAM ロールは、既定のロールを選ぶ

マウント先の EC2 で、`ls` で `aws-backup-restore_` で始まるディレクトリができたことを確認してから、必要なファイルをコピーする。
