# 複数サーバーのパスワード定期変更を、管理用 DB 1つから一括で反映する

Linux・PostgreSQL・Windows が混在する運用環境で、作業者ごとのパスワードを定期的に変えるために組んだ仕組みの設計メモ。手作業で全サーバーを回ると漏れと打ち間違いが出るので、「誰がどのサーバーのどの種類のアカウントを持つか」を DB に持ち、そこからスクリプトで各サーバーへ流す。

（2020-02 時点のメモ。コードは載せない）

## 全体の流れ

踏み台サーバー1台から、各 Linux へ SSH の鍵認証で入って実行する。番号順に1本ずつ流し、各スクリプトは実行前に対象を表示して `y` を待つ。

| 手順 | 内容 |
| --- | --- |
| 1 | 現在の適用状況を、ユーザー起点・ホスト起点の2通りで表示する |
| 2 | ユーザーやホストの増減があれば手で DB を更新する |
| 3 | ユーザーごとに新パスワードを生成して DB に書く |
| 4 | Linux の OS ユーザーを更新する（`useradd` と `chpasswd`） |
| 5 | PostgreSQL のロールを更新する（`CREATE ROLE` / `ALTER ROLE` / `DROP ROLE`） |
| 6 | Windows 用の `net user` バッチを生成する（実行は Windows 上で手で行う） |
| 7 | 新パスワードをメールで本人に通知する |
| 8 | 削除フラグの付いたレコードを DB から消す |
| 9 | `pg_hba.conf` を手で整える |

## 管理用 DB の設計で決めたこと

テーブルは3つ。ユーザー、ホスト、「ユーザーとホストの紐づけ」で、紐づけは（ユーザー ID, ホスト ID, 種類）を主キーにする。

- 種類は OS・PostgreSQL 通常ユーザー・PostgreSQL スーパーユーザーに分ける。同じ人が同じホストで OS と DB の両方のアカウントを持つので、種類を主キーに入れないと表せない
- ユーザーのレコードに `password` と `old_password` を持たせる。旧パスワードを1世代だけ残すのは、スクリプトの途中失敗や誤操作で新旧が食い違ったときに戻せるようにするため。更新のたびに「旧は捨て、現行を旧へ移し、現行を新規生成」の順で書く
- PostgreSQL のロール名は OS のユーザー名と揃えたいが、ハイフンを含む名前は引用符が要るので、ハイフンをアンダースコアに変えた列を別に持つ
- 氏名・会社名は全角、ID は所属区分ごとに番号帯を分ける、のように入力規則を決めておくと、後から一覧を見て区別しやすい
- 管理用 DB 自体に全員分の平文パスワードが載る。配布のために平文が要るので、ハッシュにはできない。代わりに、置くサーバーを「監視データより機密度が高いものと同等のサーバー」に決め、そこだけに DB を作る。スクリプトはメールを送れるサーバーに置くので、DB の置き場所とスクリプトの置き場所は別になりうる

## 削除は「印を付ける → 実機から消す → DB から消す」の順に進める

ユーザーやホストを減らすときは、DB のレコードを先に消さない。紐づけの状態列に削除印（`x`）を付け、スクリプトが各ホストから実際にアカウントを消し終えてから、別のスクリプトで DB のレコードを消す。先に DB を消すと、「どのホストにまだ残っているか」が分からなくなる。

ホストごと廃止する場合は、ホスト内の作業が要らないので、紐づけを `delete` するだけでよい。ホストを残して別案件に転用するなら、ユーザーだけ消したいので、通常の削除と同じく印を付ける。

## 運用で踏んだ点

- 各スクリプトは確認プロンプト（`y/N`）で止め、`y` 以外では何もせず終わる。破壊的な更新を連続で流すので、1本ごとに対象一覧を目で確認する
- Linux 側のエラーは、スクリプトの仕組み上ログに出ない。各ホストの `/tmp` に生成された実行ファイルが残るので、それを `sh` で手で再実行して原因を見る。何度流しても同じ結果になるように作ってあるので、再実行しても害はない。ただし、そのファイルには平文の新パスワードが入っている可能性がある。調査が済んだらすぐ消し、権限も本人以外が読めないようにしておく
- Windows は、バッチを生成するところまでを自動にして、実行は人が管理者権限で行う。バッチの先頭で `%COMPUTERNAME%` が対象ホスト名と一致するかを確かめ、別のホストで流しても何も起きないようにする。実行後のログは必ず確認する
- `pg_hba.conf` は、編集前に日付付きでコピーを取り、`diff` で差分を確かめてから `pg_ctl reload` する。接続元の IP の範囲を利用者の所属ごとに分けて書く
- DB のテーブルを作り直す手段（DROP して CREATE）も用意しておく。その場合も、先に `pg_dump` でバックアップを取る
