# MySQL のトリガー・シーケンステーブル・イベントで予約枠の整合性をデータベース側に持たせる設計例

定員のある予約枠を扱う小さな予約システムで、整合性のチェックと採番を DB 側のトリガーに寄せたときの設計メモ。アプリ側のチェックだけに頼らず、どの経路から INSERT/UPDATE されても破れない形にするのが狙い。

（2020-07 時点の設計メモ。MySQL のバージョンはメモに記録がなく、`SIGNAL` が使えるバージョンで書いている。ここに書いたトリガーの動作は設計時に確認した範囲で、同時に複数の予約が入ったときの排他は検証していない）

## テーブルの分け方

- マスタ: エリア、サービス、時間枠、休日、ユーザー、権限
- 予約枠データ（`reserve_slot`）: 日付 × エリア × サービス × 時間枠ごとに 1 行。定員と休日フラグを持つ
- 予約の状態（`reserve_state`）: 予約 1 件が 1 行。キャンセルは行を消さず、キャンセルフラグと日時を立てる
- 予約枠の「何人入っているか」は列に持たず、ビューで `reserve_state` の未キャンセル行を数える

予約人数を列で持たなかったのは、キャンセルや定員変更のたびに 2 か所を更新する必要が出て、ずれる原因になるため。

## 判断の記録

- 時間枠マスタは UPDATE せず、適用開始日付きの行を INSERT して切り替える。未来の日付で入れておけば、その日から新しい時間枠になる。過去の予約と矛盾しない
- 時間枠を INSERT したあとの AFTER INSERT トリガーで、適用開始日以降の予約枠データを削除してプロシージャで作り直す。ただし、その前の BEFORE INSERT トリガーで、適用開始日以降に予約が 1 件でもあれば `SIGNAL` で弾く
- 予約枠データは、毎日 0 時のイベントで「最大予約可能日数先」まで足りない日を作る（既にある日は何もしない）。マスタを変えた直後も同じプロシージャを呼べるので、作り方が 1 か所に集まる
- 休日は、休日マスタの INSERT/DELETE トリガーで予約枠データの休日フラグを立てたり降ろしたりする。予約枠データを作るときにも同じフラグを引く

## トリガーで弾くもの

予約の BEFORE INSERT で定員超過と休日を、予約枠データの BEFORE UPDATE で「予約が入っているのに定員を減らす・時間枠を変える・休日にする」を、それぞれ `SIGNAL SQLSTATE` で弾く。エラーごとに SQLSTATE を分けておくと、アプリ側でエラー内容を判別できる。

```sql
-- 予約の BEFORE INSERT トリガーの要点（定員超過）
SELECT int_capacity INTO @cap FROM reserve_slot
 WHERE id_reserve_slot = NEW.id_reserve_slot;
SELECT COUNT(*) INTO @cnt FROM reserve_state
 WHERE id_reserve_slot = NEW.id_reserve_slot AND flag_cancel = 0;
IF @cap <= @cnt THEN
  SIGNAL SQLSTATE '50000' SET MESSAGE_TEXT = 'reservation is full';
END IF;
```

## 採番はシーケンステーブルとトリガーで

AUTO_INCREMENT を使わず、テーブル名ごとに 1 行持つシーケンステーブルを更新して採番した。`LAST_INSERT_ID(式)` を使うと、更新と値の取得が同じ接続の中で完結する。

```sql
-- BEFORE INSERT トリガー内。ID が NULL のときだけ採番する
IF NEW.id_user IS NULL THEN
  UPDATE sequence_table SET int_seq = LAST_INSERT_ID(int_seq + 1)
   WHERE char_table_name = 'user';
  SET NEW.id_user = LAST_INSERT_ID();
END IF;
```

## 元の SQL 例の落とし穴

元の SQL 一覧に、複数列を更新する UPDATE を `SET a = 1 AND b = 2` と書いた例があった。MySQL の `SET` は列をカンマで区切るので、`AND` で繋ぐと 1 つの式として解釈され、2 列目は更新されない。`SET a = 1, b = 2` と書く（構文上の解釈で、実行は確認していない）。
