# SQL Server のバックアップを別サーバーにリストアするときに出たエラー二つ（排他アクセスが取れない、ファイルを復元できない）

別サーバーで取ったデータベースの完全バックアップ（.bak）を、検証用の SQL Server に `sqlcmd` で RESTORE したときに出たエラーと、そのときの対処のメモ。

（2019-07 時点のメモ。SQL Server のバージョンはエラーの記録からは特定できない（移行手順の別メモは 2016 と 2005 を扱っている）。サーバー名・DB 名・パスは仮の名前に置き換えた）

## 1. 「データベースは使用中なので、排他アクセスを獲得できませんでした」(メッセージ 3101 / 3013)

既存のデータベースを上書きしようとして、既に接続しているユーザーがいると出る。

```
RESTORE DATABASE <DB名> FROM DISK = N'<bakのパス>'
-- メッセージ 3101: データベースは使用中なので、排他アクセスを獲得できませんでした。
-- メッセージ 3013: RESTORE DATABASE が異常終了しています。
```

`WITH REPLACE` を付けても同じエラーになる。REPLACE は「既存のデータベースを上書きしてよい」という指定で、接続中のセッションを切るものではない。

当時の対処は、担当者に連絡してセッションを切ってもらうこと（実際には DB を再起動した）。リストアの前に、接続している人がいないかを確認する。

## 2. 「ファイル '...' を '...' に復元できません。WITH MOVE を使用して…」(メッセージ 5133 / 3156)

バックアップ元と、リストア先でデータファイルの置き場所が違うと出る。バックアップにはデータファイル・ログファイルの元のパスが入っていて、リストア先に同じパスのディレクトリが無いと、ディレクトリ参照の失敗（OS エラー 3、指定されたパスが見つかりません）になる。

```
RESTORE DATABASE <DB名> FROM DISK = N'<bakのパス>'
-- メッセージ 5133: オペレーティング システム エラー 3(指定されたパスが見つかりません。) により、
--   ファイル "<元のデータフォルダ>\<DB名>.mdf" のディレクトリ参照に失敗しました。
-- メッセージ 3156: ファイル '<論理名>' を '<元のデータフォルダ>\<DB名>.mdf' に復元できません。
--   WITH MOVE を使用して、そのファイルにとって有効な場所を特定してください。
```

当時の対処は、リストア先の既存の設定（データファイルの置き場所）を確認して、データベースを新しく作ってから戻すこと。`WITH MOVE` でデータファイルとログファイルの移動先を指定する方法もある（[RESTORE の公式ドキュメント](https://docs.microsoft.com/ja-jp/sql/t-sql/statements/restore-statements-transact-sql)）。

## 補足: データ移行ウィザードを使うとき

SQL Server のインポートおよびエクスポート ウィザードで SQL Server 同士（2016 から 2016、2005 から 2016）を移す手順書も作っていた。ウィザードには 64 ビット版と 32 ビット版があり、データソースに 32 ビットのデータプロバイダーが必要だと分かっている場合を除いて 64 ビット版を使う。移行元はデータソースに「SQL Server Native Client 11.0」を選び、サーバー名を入れ、SQL Server 認証でユーザー名とパスワードを指定する。
