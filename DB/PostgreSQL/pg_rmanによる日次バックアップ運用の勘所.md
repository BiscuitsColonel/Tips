# pg_rman でフルと増分を回す運用の勘所（保持期間の数え方・PITR の注意）

pg_rman を使ったオンライン物理バックアップを、週次フル・日次増分で運用したときの設計と、設定ファイルや PITR で気をつけた点。インストール手順やコマンド一覧は [pg_rman の GitHub](https://github.com/ossc-db/pg_rman) を見る。

（2020-03 時点の運用メモ。PostgreSQL 11 で構築。PITR の `recovery.conf` は PostgreSQL 12 で廃止された）

## 設計

- 土曜日にフルバックアップ、日曜日から金曜日は増分
- 保持は 1 週間から 2 週間
- ローカルに溜まったバックアップを日次で圧縮し、外部のストレージへ上書きコピーする。ローカルにも、自動ローテーションで消えるまで残す

バックアップ後は必ず `pg_rman validate` を実行する（検証しないバックアップは使えるか分からない）。ローテーションで消えるのは削除マークが付いただけなので、`pg_rman purge` で物理的に消す。

## 配置と設定の落とし穴

- バックアップカタログ（`BACKUP_PATH`）と WAL アーカイブ先（`ARCLOG_PATH`）は `$PGDATA` と同じ場所に置かない。PITR でデータディレクトリを入れ替えると一緒に消えてしまう
- `COMPRESS_DATA = YES` で約 6 分の 1 になった
- `KEEP_DATA_DAYS` は「バックアップの日数」で数える。**増分は、フル + 増分がひと組そろったときに 1 日分として数える**。日数を 7 にしたときの実際の保持はこの数え方に従う
- `KEEP_DATA_GENERATIONS` の世代はタイムライン（TLI）の数。世代はバックアップをリストアしたときに変わる
- 当日とその前日分は、閾値に関係なく必ず残る
- 古いバックアップは設定の閾値を超えると削除対象になるが、purge が必要

## リストアと PITR

- `pg_rman restore` を引数なしで実行すると、最小のタイムラインの中で最新のバックアップが対象になる。タイムラインは `--recovery-target-timeline` で、時刻は `--recovery-target-time` で指定する
- PostgreSQL 11 までの PITR で `recovery.conf` に書くパラメーターのうち、`recovery_target_action` のデフォルトは `pause`。到達後に停止して接続を受け、`SELECT pg_wal_replay_resume()` で再開するまで終わらない。`hot_standby` が無効だと `pause` は `shutdown` と同じ動きになる
- `recovery_target_action = shutdown` にしたときは、`recovery.conf` が名前変更されないので、設定を直すか手で消さないと次の起動もすぐ停止する
- 時刻の指定が複数あると、最後に指定したものが使われる（PostgreSQL 9.4 以降）

## 外部ストレージへ退避するスクリプトの作り

（同じ運用の 2020-03 時点のメモ。退避は外部ストレージを 2 か所に分けて書いた）

- 退避ファイルの名前に曜日を付ける（増分と pg_dump は `date +%a`、フルは固定名で上書き）と、掃除処理を書かなくても 1 週間分で回る
- 最初にマウント先を `df` で確認し、マウントされていなければ `mount` する。それも失敗したらその場で中止して、エラーをシステムログへ出す
- `rsync` は失敗しても数回（4 回、間隔 5 秒）やり直し、全部失敗したらログに残して終了する。ネットワークストレージ側の一時的な失敗で毎回止まらないようにするため
- フルの tar からは WAL アーカイブとサーバーログのディレクトリ、pg_dump の出力先を除外する（それぞれ別に扱うため）

## 日次のリストア確認用の目印テーブル

毎日、日付入りのテーブル（`T20200319` のように英字から始める。数字から始まる名前は引用符が要るため）を作り、前日分を `DROP` するスクリプトを cron に入れた。リストアしたデータベースに存在する目印テーブルの日付が、そのバックアップがどの日の時点かを示す。バックアップが取れていることと、日付どおりに戻せていることを、テーブルが 1 つ在るかどうかで確かめられる。

```sh
psql -U postgres -d postgres -c "create table T`date +%Y%m%d` ();"
psql -U postgres -d postgres -c "drop table T`date +%Y%m%d -d '1 day ago'`;"
```
