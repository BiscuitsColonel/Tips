# COPY から INSERT 文を作る、ログの実行時間を SQL ごとに集計する、継承パーティションを一括で作るシェルのメモ

検証や運用の手間を減らすために書いた小さなシェルの要点。どれも使い捨てに近いもので、制約も書いておく。

（2020-06〜2021-03 時点のメモ。PostgreSQL のバージョンは元メモに記載なし。ホスト名・ファイルのパスは仮のものに置き換えた）

## COPY の出力を使って INSERT 文を作る

データの一部を別の環境に INSERT 文で持っていきたいとき、COPY の CSV 出力を整形して作る。区切りを `@`、囲み文字を `'` にして、文字列の列だけを `FORCE QUOTE` で囲む。出力の時点で SQL の文字列リテラルの形になるので、あとは `sed` で括弧とカンマを足すだけで済む。

```sh
# 1. COPY で出力する（区切り @、囲み文字 '、文字列の列を FORCE QUOTE）
psql -d <DB> -c "COPY (SELECT * FROM <表> LIMIT 10000)
  TO '/tmp/data.csv' WITH CSV DELIMITER '@' QUOTE '''' FORCE QUOTE <文字列列1>,<文字列列2>"

# 2. 整形して INSERT 文にする
cp /tmp/data.csv /tmp/data.ins
sed -i 's/^/(/g'      /tmp/data.ins        # 行頭に (
sed -i 's/$/),/g'     /tmp/data.ins        # 行末に ),
sed -i '1i INSERT INTO <表> VALUES' /tmp/data.ins
sed -i '$ s/,$/;/g'   /tmp/data.ins        # 最終行のカンマを ; に
sed -i 's/@/,/g'      /tmp/data.ins        # 区切りの @ を , に
```

同じ CSV を `COPY <表> FROM ... DELIMITER '@' CSV QUOTE ''''` で読み戻せるので、出力が正しいかをその場で確かめられる。

使うときの制約（スクリプトを読んだ限りの指摘）。

- データに `@` が含まれると、最後の置換で壊れる
- CSV 形式の COPY は NULL を空で出すので、NULL を含む列では INSERT 文の構文が崩れる

## ログの duration 行を SQL ごとに集計する

ログに出した `duration: ... ms` の行から、同じ SQL 文の実行回数・最大・最小・平均を出す。ログから `INSERT INTO` で始まる文を `awk` の `match` で拾い、文ごとに、その文を含む duration 行を `grep -o "duration: [0-9]*.[0-9]* ms"` で抜いて数値だけにし、`wc -l` で回数、`awk` で最大・最小・平均を出す。文ごとに `sql_<連番>.log` へ書き出す。

SQL 文をそのまま `grep` するので、定数が違えば別の文として扱われる。同じ形の SQL をまとめたいなら、`pg_stat_statements` を使うほうが手間がない。

## 継承パーティションの子テーブルを、最新の子から複製して一括で作る

月次の継承パーティションで、次の数か月分の子テーブルをまとめて作る。DDL を一から組み立てず、最新の子テーブルの DDL を `pg_dump -s -t` で取り、名前と範囲の月を `sed` で書き換える。

1. `pg_inherits` と `pg_class` から、親テーブルの子の最大の名前を取る。名前の末尾 6 桁を YYYYMM として読む
2. 作る月は `YYYYMM + 1` で出し、月が 13 になったら `+ 88` して翌年 1 月にする（201913 を 202001 にする計算）
3. `pg_dump -s -t <最新の子>` の出力から `SET` と `SELECT` の行を消し、最新の月を新しい月に、範囲の境界の月も新しい月に置換する
4. 作る数だけ 3 を繰り返し、最後に `psql -f` で流す。実行前に作る内容の確認（y/N）を挟む

前提は、子テーブル名の末尾が YYYYMM で、CHECK 制約などの範囲の値も同じ形で DDL に現れること。この前提が崩れると置換が空振りするので、実行前に出力した DDL を目で確かめる。

スクリプトを読んだ限りの指摘として、最新の子テーブルの DDL に含まれる「翌月・翌々月」の検索用の値は、繰り上げの `+ 88` を月の変数にしか足していない。最新の子が 12 月のときは、検索する値が実際の DDL の値と合わず、置換が空振りしそう（実機での検証はしていない）。
