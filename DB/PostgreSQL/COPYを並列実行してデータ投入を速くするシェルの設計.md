# psql の COPY をファイル分割とテーブル分割で並列実行する投入シェルの設計と落とし穴

（2020-07 時点に書いた自作シェル `pg_copy` のメモ。PostgreSQL のバージョンに依存する書き方は無い。計測結果はスクリプトに残っていないので、速度の数字は載せない）

CSV ファイル、または別サーバー・別テーブルから、psql の `\copy` を複数プロセスで同時に走らせて投入する。1本の COPY は1プロセスで書くため、巨大なデータの投入が単一コアに縛られるのを避けるのが目的。

## 使い方の形

ファイルから投入するか、テーブルから投入するかを、渡したオプションの組み合わせで判定する（`-f` はファイル、`-t` は投入先テーブル、`-T` はコピー元テーブル）。

```sh
# ファイル → テーブル（4並列）
pg_copy.sh -f /data/big.csv -t public.target -c 4 -C , -A Y
# 別DBのテーブル → テーブル（4並列）
pg_copy.sh -T public.src -H srchost -D srcdb -t public.target -c 4
```

## 肝の工夫

### ファイルは「行を壊さずに N 分割」して xargs で並列にする

`split -e -n l/i/N file` は、ファイルを行の境界でちょうど N 個に分けた i 番目を標準出力に出す。これを `xargs -P N` で N 個並べ、それぞれを `psql -c "\COPY tbl FROM STDIN ..."` にパイプする。分割した一時ファイルを作らずに済む。

```sh
for i in $(seq ${N}); do
  echo "split -e -n l/${i}/${N} ${FILE}"
done | xargs -P ${N} -I XXX bash -c "XXX | psql -c \"\COPY ${TABLE} FROM STDIN CSV\""
```

ヘッダ行があるファイルは、1番目の断片だけ `| tail -n +2` を付けて先頭行を落とす。

### テーブルからテーブルは LIMIT / OFFSET で分ける

コピー元の件数を `SELECT COUNT(*)` で取り、`件数 ÷ 並列数` ずつ `COPY (SELECT * FROM src LIMIT n OFFSET m) TO STDOUT CSV` を、投入側の `\COPY ... FROM STDIN CSV` へパイプして、バックグラウンド（`&`）で走らせる。最後の断片だけ LIMIT を付けない。

## コードを読み返して気づいた落とし穴

- テーブル分割の `SELECT` に `ORDER BY` が無い。並列で別々のスナップショットから取るため、読んでいる間にコピー元が更新されると、取りこぼしや重複が起きうる（計測も再現もしていない）。主キーで範囲を切るか、更新の無いテーブルに限るべき
- テーブル分割はバックグラウンドで起動して `wait` するだけなので、断片のどれかが失敗しても終了コードに出ない。ファイル分割は `xargs` が失敗を非0で返すので検出できる
- 件数より並列数が大きいと `件数 ÷ 並列数` が 0 になり、`LIMIT 0` の断片ができて最後の断片に全件が寄る。先に弾く検査が要る（元のスクリプトにこの検査が入っているかは未確認）
- パスワードはオプションにせず `~/.pgpass` か `PGPASSWORD` に任せる作りにしてあり、スクリプトには持たない

## 同じフォルダにあった周辺スクリプトは載せない

pandas の `to_csv` と `copy_expert` で CSV を入出力する検証用スクリプトや、SQL をファイルから1行ずつ実行して結果をログ用テーブルに COPY するスクリプトも作ったが、手順に独自の工夫は無いので載せない。
