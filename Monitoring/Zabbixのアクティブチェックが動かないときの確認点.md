# Zabbix のアクティブチェックが動かないときのエラーメッセージ別の確認点

Zabbix エージェントのアクティブチェックが失敗するとき、`zabbix_agentd.log` に出るメッセージから設定のどこを見るかを引く。

（2020-05 時点のメモ。）

## パッシブとアクティブの違い

| | 通信の向き | 値の取得 | ポート |
| --- | --- | --- | --- |
| パッシブ | サーバ -> エージェント | サーバがエージェントに問い合わせて返してもらう | エージェント側 10050/TCP が開いていること |
| アクティブ | エージェント -> サーバ | エージェントがサーバから監視項目の一覧をもらい、自分で収集して送る | サーバ側 10051/TCP が開いていること |

アクティブが失敗したら、まずエージェントのログを見る。ログは Linux なら `/var/log/zabbix/zabbix_agentd.log`、Windows ならインストール先の `zabbix_agentd.log`。アイテムやトリガの問題ではなく、設定（config）の問題であることがほとんど。

## メッセージ別

### `active check configuration update from [<サーバ>:10051] started to fail (cannot connect to [[<サーバ>]:10051]: Connection refused)`

サーバに接続できていない。サーバ側で 10051/TCP が待ち受けているか、間にファイアウォールが無いかを見る。`ServerActive` の IP とポートが正しいかも確認する。

### `no active checks on server [<サーバ>:10051]: host [<ホスト名>] not found`

サーバは繋がっているが、そのホスト名がサーバに登録されていない。次の 2 点を見る。

- エージェントの `Hostname` と、Zabbix サーバに登録したホスト名が大文字小文字まで一致しているか。たとえば `Hostname=Host01` と書いたのにサーバ側に `host01` で登録していると、ダメになる
- `HostnameItem=system.hostname` で自動取得している場合は要注意。Windows ではホスト名がすべて大文字で返るので、サーバ側の登録名も大文字にそろえる

### 接続はできているのに値が来ない

- エージェント側の `ServerActive` に、サーバ側で指定している IP アドレスと同じものを書く。`127.0.0.1` のようなループバックではなく、エージェントから見たサーバの実 IP を指定する
- サーバ側の `ListenIP` を明示している場合は、その IP と `ServerActive` が合っているか見る（`ListenIP` を書かなければ全インターフェースで待ち受ける）

## 正常に始まったとき

次のログが出れば OK。

```text
agent #5 started [active checks #1]
```
