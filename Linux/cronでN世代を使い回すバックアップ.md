# cron だけで N 世代を使い回すバックアップ（日数を N で割ったあまりをサフィックスにする）

古い世代を消す処理を書かずに、ファイルを N 世代ぶんだけ残したいときの cron ジョブの書き方。バックアップ先のファイル名に「1970-01-01 からの経過日数を N で割ったあまり」を付けて、同じ名前を N 日ごとに上書きする。

（2021-10 時点のメモ。Ansible の cron モジュールで各サーバーに配布していた構成から、この部分だけ取り出した）

## 仕組み

N を 30 にすると、サフィックスは 0〜29 を毎日順に回る。30 日前のファイルは同じサフィックスで上書きされるので、削除の処理は要らない。

```sh
FROM=`date -d'1970/01/01' +%s`
TO=`date +%s`
DIFF=`expr \( ${TO} - ${FROM} \) / 60 / 60 / 24`
SUFFIX=`/usr/bin/expr \( ${DIFF} % 30 \)`
cp -fp /path/to/source /path/to/backup_${SUFFIX}
```

リモートへ送る場合は、最後の行を `scp` に替える。

```sh
/usr/bin/scp -prq -i /root/.ssh/<key> /path/to/source <user>@<backup-host>:/path/to/backup_${SUFFIX}
```

## 注意

- `FROM` をローカルタイムゾーンの 1970/01/01 0 時として求めているので、サフィックスが切り替わるのはローカルの 0 時になる
- 保持日数 N を途中で変えると、サフィックスの対応がずれるので、変更直後は新旧の世代が混ざる
- 元の構成では、cron に渡すコマンドの `%` をエスケープせずに書いていた。動作の記録は残っていない。cron に直接書くときは `\%` にするか、スクリプトに切り出すこと
